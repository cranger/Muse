Privacy Policy

Last updated: October 2, 2026

1. Introduction

cranger muse ("the app") is a personal automation built and operated by a single individual for their own use. It connects a private AI assistant to the owner's Google Chat account so the assistant can surface reminders, direct questions, and time-sensitive updates from the owner's chats. The app is not offered as a service to anyone else, has no other users, and collects data from exactly one Google account: the owner's.

This policy explains what Google user data the app accesses, why it accesses it, and how that data is handled, stored, and protected.

2. Data we collect

The app accesses the owner's Google Chat data exclusively through the official Google Chat API, after the owner grants permission on Google's OAuth consent screen. The app requests the following OAuth scopes, and accesses only the data those scopes permit:

  • chat.spaces — the list of the owner's chat spaces (direct messages and group spaces), including space names and membership rosters, so the app knows which conversations to check.
  • chat.messages — the text content, timestamps, and sender information of messages in the owner's spaces, so the assistant can identify reminders, questions, and time-sensitive updates addressed to the owner.
  • chat.memberships — membership details of the owner's spaces, used to understand who participates in each conversation.
  • chat.messages.reactions — emoji reactions on messages, used only as additional context when summarizing a conversation.
  • directory.readonly — basic directory information, used to resolve the display names of message senders.
  • userinfo.profile — the owner's basic profile information (name and profile photo), used to identify the owner's own messages so they can be excluded from alerts.

The app does not access Gmail, Google Drive, Google Calendar, or any other Google service. It does not collect location data, contacts outside of chat memberships, or any data from any person other than through the owner's own chat spaces.

3. How we use the data

Data accessed through the API is used for a single purpose: to help the owner stay on top of their Google Chat conversations. Concretely, the app:

  • Periodically reads recent messages in the owner's spaces.
  • Identifies messages that contain reminders, direct questions, requests, or time-sensitive information (for example, family logistics or school updates).
  • Presents concise summaries of those items to the owner through their private assistant.

The app operates read-only by default: it never sends messages, creates spaces, modifies memberships, or takes any other write action unless the owner explicitly instructs it to in a given moment. Message content is processed transiently in memory to produce summaries; the app does not build profiles, train models, or perform analytics on the data.

AI and machine learning

Google user data accessed through the API is not used to develop, improve, or train generalized (non-personalized) AI or machine learning models. Message content is processed solely to provide the user-facing summarization feature described above — identifying reminders, questions, and time-sensitive updates for the owner.

4. Data storage and security

  • OAuth tokens. The OAuth access and refresh tokens that authorize API access are stored on the owner's private home server, in files readable only by the owner's user account. They are never transmitted anywhere except to Google's OAuth and API endpoints.
  • Message content. Chat messages are fetched on demand and held in memory only for the duration of processing. The app keeps small operational watermarks (such as the timestamp of the last message checked in each space) so it does not re-read the same messages; it does not maintain a persistent archive of message contents.
  • Security practices. API communication uses TLS-encrypted HTTPS connections to Google's servers. The home server is on the owner's private network and is not exposed to the public internet.

5. Data sharing

The app does not sell, rent, or share Google user data with any third party. Data is disclosed only as follows:

  • To Google's API servers, as required to make the authorized API calls described above.
  • If required by law, in which case disclosure is limited to what is legally compelled.

There are no advertisers, analytics providers, data brokers, or other third parties with access to the data.

6. Data retention and deletion

Operational watermarks (per-space timestamps) are retained until the owner deletes them or decommissions the app. OAuth tokens persist until the owner revokes access or deletes them.

The owner can stop all data collection at any time by revoking the app's access on the Google account permissions page. Revocation takes effect immediately: the app can no longer call the API, and any stored tokens become useless. To delete stored tokens and watermarks from the home server, the owner may delete the app's credential files directly.

7. Changes to this policy

If this policy changes materially, the "Last updated" date above will be revised. Because the app has a single user — its owner and operator — changes are made solely at the owner's discretion.

8. Contact

Questions about this policy can be directed to the app owner through the Google Cloud project associated with this app.
