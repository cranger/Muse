Privacy Policy

Last updated: October 4, 2026

1. Introduction

web-assistant ("the app") is a personal web dashboard built and operated by a single individual for their own use. It runs on the owner's home server and connects to the owner's Google account so the owner can triage email, view their calendar agenda, and manage tasks from one place. The app is not offered as a service to anyone else, has no other users, and collects data from exactly one Google account: the owner's.

This policy explains what Google user data the app accesses, why it accesses it, and how that data is handled, stored, and protected.

2. Data we collect

The app accesses the owner's Google data exclusively through Google's official APIs, after the owner grants permission on Google's OAuth consent screen. The app requests the following OAuth scopes, and accesses only the data those scopes permit:

  • gmail.modify — read the owner's messages (metadata and bodies) so the dashboard can display, categorize, and summarize inbox threads; modify message labels to archive, mark as spam, or star messages when the owner acts on them; and send email replies the owner composes in the dashboard. The app does not access Gmail settings.
  • calendar.events — read events across the owner's calendars to render the agenda views, and create, edit, or delete events when the owner adds or changes them in the dashboard.
  • tasks — read the owner's task lists and create, complete, or delete tasks the owner manages in the dashboard.
  • spreadsheets — read values from the owner's spreadsheets, executed through the owner's own Apps Script, to power the dashboard's stock ticker (quote data the script reads from the owner's sheet).

The app does not access Google Drive files, Google Contacts, Google Photos, or any other Google service. It does not collect location data, and it does not collect data from anyone other than through the owner's own account.

3. How we use the data

Data accessed through the APIs is used for a single purpose: to run the owner's personal dashboard. Concretely, the app:

  • Lists and displays the owner's inbox threads, including message content, so they can be read and triaged.
  • Categorizes messages and generates short thread summaries using an AI model (see below), so the owner can scan the inbox quickly.
  • Applies the owner's own archive, spam, star, and reply actions to Gmail.
  • Renders today's and upcoming calendar events and the owner's task lists, and records the task and calendar changes the owner makes.
  • Fetches the owner's spreadsheet-backed stock data through the owner's Apps Script for the dashboard ticker.

AI and machine learning

Email text (subjects, bodies, and generated summaries) is sent to the Ollama hosted model API solely to provide the user-facing categorization and summarization features described above. The data is processed transiently for that request; Google user data accessed through the APIs is not used to develop, improve, or train generalized (non-personalized) AI or machine learning models.

4. Data storage and security

  • OAuth tokens. The OAuth access and refresh tokens that authorize API access are stored in the app's database on the owner's home server, accessible only to the owner's user account. They are never transmitted anywhere except to Google's OAuth and API endpoints.
  • Cached content. The dashboard caches summaries and metadata (such as message categories, thread summaries, and per-space watermarks) in its database so it does not re-process the same content; these caches are refreshed as new mail arrives and can be cleared by the owner.
  • Security practices. API communication uses TLS-encrypted HTTPS connections to Google's and Ollama's servers. The home server is on the owner's private network and is not exposed to the public internet.

5. Data sharing

The app does not sell, rent, or share Google user data with any third party. Data is disclosed only as follows:

  • To Google's API servers, as required to make the authorized API calls described above.
  • To the Ollama hosted model API, for the transient categorization and summarization processing described in section 3.
  • If required by law, in which case disclosure is limited to what is legally compelled.

There are no advertisers, analytics providers, data brokers, or other third parties with access to the data.

6. Data retention and deletion

Cached summaries and metadata are retained until refreshed, cleared by the owner, or the app is decommissioned. OAuth tokens persist until the owner revokes access or deletes them.

The owner can stop all data collection at any time by revoking the app's access on the Google account permissions page. Revocation takes effect immediately: the app can no longer call the APIs, and any stored tokens become useless. To delete stored tokens and cached data from the home server, the owner may delete the app's credential files and database records directly.

7. Changes to this policy

If this policy changes materially, the "Last updated" date above will be revised. Because the app has a single user — its owner and operator — changes are made solely at the owner's discretion.

8. Contact

Questions about this policy can be directed to the app owner through the Google Cloud project associated with this app.
